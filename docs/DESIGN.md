# 设计约定

## 使用方式

首版面向 Windows：电脑运行 Agent，硬件显示状态并接收交互。先接电脑，暂不要求关机后独立运行。关机或休眠时不能持续提醒。

## 角色与任务

桌宠可以提出学习计划；用户确认后才写入任务库。初期完成情况依靠使用者确认，不声称能够判断真实学习状态。允许延期、跳过和安静时段。

模型负责理解和建议，程序负责保存与执行。提醒时间保存在数据库，由确定性的调度机制检查，不让模型自行等待或计算后台计时。

当前 CLI 是底层任务操作工具；尚未对接计划确认界面或模型工具调用。

## 资讯

优先使用官方发布、论文和开源项目原始来源。保留标题、原文 URL、发布日期、抓取时间与来源；区分原文事实与模型解释。资料不足时说明不足。优先保存链接及短摘要，避免把完整文章复制到仓库。

## 音频

首版先按键开始说话。电脑音响、麦克风优先采用现成设备，屏幕和音频可以使用不同 USB 接口。开发板自带麦克风和扬声器不等于已支持 Windows USB 音频。

计划提供收音指示、停止录音和会议暂停模式。语音记录默认不保留；实际实现这些规则后再宣称支持。

## 数据与模型

任务数据默认仅保存在本机 `.local/`。未来使用云端模型时，需在配置说明中明确哪些文字或音频会发送到服务商，提供调用费用控制与可替换的适配层。

## 首版评测

关注任务保存与重启恢复、资讯引用是否正确、提醒是否重复、语音响应延迟、音频设备拔插恢复。不用未经测量的准确率和延迟作为项目宣传。

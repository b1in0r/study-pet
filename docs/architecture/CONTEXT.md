# 上下文管理

状态：待实现。当前网页的 daily_context 只是规则摘要，没有模型上下文管理器。

## 1. 四层信息与可信边界

| 层 | 内容 | 加载方式 |
| --- | --- | --- |
| 固定规则 | 助理职责、工具边界、输出格式 | 源码中的版本化提示词；每次调用必带 |
| 核心个人上下文 | 已确认背景、当前阶段、关键偏好和约束 | 查询 active 且有效的结构化事实，生成精简档案 |
| 当前会话 | 当前问题、最近完整消息、未闭合工具交互和有效摘要 | 只加载本会话；按预算裁剪 |
| 按需知识 | 相关手动笔记、历史片段、任务、文档与最新检索资料 | 先按范围与可用性过滤，再检索排序 |

原始历史可长期保留，但模型每次只看到当前问题所需的部分。跨会话学习通过事实库和带引用的检索完成，不把所有会话直接拼在一起。

用户事实、文档和网页均作为带类型的数据块，不作为系统指令。附件里“忽略规则”“调用工具”等文字只是资料内容。通用规则的来源只能是受控源码与配置；不让文档改变工具白名单。

## 2. 一次请求的装配过程

1. **保存输入**：生成应用 message ID 和 conversation seq，记录用户可见文本；创建 run，保存 prompt/context 策略版本。未完成旧 run 由恢复流程标为 interrupted。
2. **确定问题范围**：如学习、求职、收入探索、通用。可以是多标签；不明确时先使用最小上下文，必要时询问，不能把分类器输出保存成用户人生方向。
3. **读取权威记录**：确认事实、当前任务与用户选定目标。当前任务状态从 tasks 读取，状态变化从 task_events 读取；摘要不能替代实时任务状态。
4. **检索相关来源**：按 source 状态、版本、处理范围、时间和问题领域过滤，再进行结构化/关键词检索。跨会话只取有引用的相关片段。
5. **校验来源与冲突**：检查当前记录仍存在且可用。分清当前偏好与过去偏好、用户陈述与模型推测。缺乏依据时明确未知。
6. **装配预算**：保留固定规则与当前问题，再依优先级放入事实、会话、任务和检索片段。生成一次调用的 context_items 清单。
7. **调用模型/工具**：工具结果限定大小并作为数据返回。每一次后续模型调用重新计预算、确认 source 状态，不能无限追加结果。
8. **保存结果**：持久化最终可见回复、运行状态和 usage；提取记忆候选与计划草稿，交由对应服务处理。

服务端记录内部 source ID。界面显示可点击的实际来源：对话日期/片段、记忆本条目、任务记录或文档页码。来源标签由程序分配；模型编造的 ID 不能直接渲染为引用。

发送云端请求前做最后一次来源有效性和版本检查；已发送的请求不能撤回。删除发生后不再把其内容用于后续调用，并清除依赖它的本地缓存。

## 3. 初始 token 预算

下面是首版可配置目标，须结合实际模型上下文窗口调整；不是模型供应商能力声明。

| 内容 | 目标上限（输入 token） |
| --- | ---: |
| 系统规则和工具定义 | 1,500 |
| 当前问题 | 1,000 |
| 核心个人事实 | 1,500 |
| 当前任务/目标 | 1,000 |
| 最近会话及有效摘要 | 3,000 |
| 相关长期记忆 | 1,000 |
| 文档/网页检索片段 | 1,500 |
| 工具结果 | 1,000 |
| 调整余量 | 500 |
| **输入合计** | **12,000** |

另预留最多 2,000 token 输出，并满足 `输入 + 输出预留 + 协议安全余量 <= 模型实际上下文窗口`。较小模型相应缩减可选材料；余量不可当成额外输出额度。

当前问题超出单项预算时，优先借用其它可选配额；仍放不下就提示拆分或按文档导入，不能悄悄截断问题。固定规则、工具协议和当前问题是必需项；总量装不下就停止调用并给出可操作提示。

计量优先采用目标模型 tokenizer。没有时用 UTF-8 字节长度作保守估算并标记 estimated，通过供应商返回 usage 校准；不使用“中文字符数等于 token 数”。未知上下文窗口需要配置清楚，不通过试探性超长请求猜测。

工具输出先截取相关片段，超长结果保存在本地可查记录里并保留定位。裁剪必须保持消息/工具调用与返回的完整组合，不能留下悬空 tool-call ID。

## 4. 摘要与压缩

摘要仅是可重建派生数据，不能将候选推断升级为事实。结构包括：讨论主题、用户明确陈述、已确认决定、待澄清问题、完成/失败动作及来源 ID。

- 每份摘要记录 `from_seq..through_seq`、源消息 revision 和提示词版本。
- 只摘要 complete 消息及已确定结果的工具交互。流式中间内容、失败回复和隐藏推理不参与记忆提取。
- 已摘要的旧消息与摘要不重复注入；最近消息保持原文，引用片段按来源 ID 去重。
- 编辑/删除源消息、撤下来源、修改相关个人事实后，检查依赖并使受影响摘要 stale；未能验证依赖的旧摘要不使用。
- 生成失败保留原始历史，临时退回更短会话窗口；不能谎称已经记住。
- 优先从原始消息范围重建，限制多轮“摘要的摘要”造成的信息漂移。
- 摘要和检索预算由真实使用评测调整，不能仅以压缩率判断质量。

## 5. 记忆写回与纠正

“回复说记住了”需要以存储工具的成功结果为准。runtime 使用明确的 `propose_memory` / `confirm_memory` 结果，不凭一句模型文本宣布持久化成功。

手动表单或明确“记住 X”的输入经校验可确认保存；一般聊天自动提取的是候选。候选包含来源和原句定位，支持批量查看、接受、修改或拒绝。重复候选按键与规范化值去重；遇到不同值时保留冲突，不能拼成互相矛盾的画像。

例如虚构用户原先选择“城市甲”，后来明确改为“城市乙”：保留两个有时间的版本，当前建议使用新值；询问“上个月为什么选城市甲”时再按当时有效期检索旧值。第一版不必自动推断所有历史生效区间，不知道时间时说明记录时间与实际生效时间的差别。

投递状态、offer 状态、学习水平和副业收入分别建事实键。用户说希望拿到 offer 只能存愿望，不能转换为已拿到；问过某技术只能存学习线索，不能转换为精通。能力结论附项目讲解、独立练习或用户自评来源，并保留其性质。

## 6. 缓存与主动行为

缓存键至少包含 conversation/message 边界、prompt 版本、context 策略、模型配置、来源版本集合和 processing scope。TTL 仅作为性能控制，不能代替删除/纠正失效检查。

第一阶段先不做跨请求缓存，避免过早引入难以清理的个人内容副本。供应商 prompt cache 是费用/性能能力，不能当作应用的持久记忆。

现有 5 秒提醒检查不调用模型。复盘和资讯简报将来使用独立、可关闭的定时流程，设置调用频率与费用预算；提醒记录本身由现有数据库调度保证。

默认没有后台屏幕监控、键盘监控或自行扫描全部磁盘。学习状态来自用户反馈和授权导入的产出记录，不能把“电脑在运行”解释为在学习。

## 7. 开发者上下文

开发新功能时先读根目录 AGENTS.md、本目录入口和对应设计页；用 git diff 与源码核对当前实现。开发规则与用户个人记忆分开。

评测只使用 `evals/` 里的虚构用户。个人资料导出、调试用上下文清单与完整请求都只能写入 `.local/`，不得复制到公开测试或提示词示例。

每个开发提交说明实现到哪一步、表版本是否改变，以及哪些假设尚未验证；后续 Codex 会话无需重新扫描个人聊天才能接手工程。

# 个人资料库

打开[本地资料库](http://127.0.0.1:8765/library)，或在计划页面右上角点击“资料库”。
这是 StudyPet 助理的持久资料来源，目前提供保存、提取、查找和校正；模型对话与自动记忆候选尚未接入。

## 使用

1. 在文件窗口按住 Ctrl 或 Shift 多选，也可以点“继续选择文件”分几次添加。确认待导入列表后，点击“导入资料”。提取期间保持页面打开。
2. 点击资料标题，核对提取文字；可以下载原件、查看图片或补充/校正文字。
3. 用关键词查找已提取内容，结果保留 PDF 页码、Word 段落或文本行号。
4. 取消“允许在资料库中检索”后，原件保留，搜索不再返回它。
5. 删除会移除本地原件及提取文字，撤下来源；已有备份不会自动修改。

导入前可选择「秋招求职」「研究生科研」「本科经历」「工作经历」或「未分类」，分类会应用到本批文件。整理已有资料时，在资料列表点「批量分类」，勾选文件，再选目标分类和「应用分类」。筛选后使用「全选当前列表」只选中当前分类。关键词搜索也在当前分类内查找。

每份资料有一个主分类，按主要用途归类。例如投递版简历放「秋招求职」，论文和实验记录放「研究生科研」。旧资料初始为「未分类」。

首次建议导入个人简介、简历、阶段目标与学习笔记，再逐步增加资料。不同版本的简历属于有日期的材料，后续模型读取时需要区分事实与目标。

## 格式和边界

| 格式 | 当前处理方式 |
| --- | --- |
| PDF | 提取文字并保留页码；无文字页尝试 Windows 本地 OCR |
| Word `.docx` | 提取正文与表格文字、保留段落编号；不提取嵌入图片、页眉或批注 |
| `.md` / `.txt` | 提取文本、保留起始行号；支持 UTF-8、带 BOM 的 UTF-16 和 GB18030 |
| PNG / JPG / JPEG / WEBP / BMP | 保存原件、图片预览、Windows 本地文字识别；不分析照片、图表或公式的视觉含义 |

旧版 `.doc` 请先另存为 `.docx`。不支持的格式会在导入时说明，不会上传到外部转换服务。

每份最多 20 MB、PDF 最多 150 页、提取文字最多 30 万字符、图片最多 2500 万像素。
扫描 PDF 每份最多尝试 12 个无文字页的 OCR，超过部分在状态提示中说明。
混合文字与图片的 PDF 页主要提取现有文字层，不保证识别其中全部图片文字。
解析在单独进程运行，90 秒超时会停止；原件保留，可手动补充文字。

OCR 有识别误差；首次使用依赖 Windows 安装的 OCR 语言。本机已验证中文图片和单页扫描 PDF。
其它系统仍可使用文本、DOCX、带文字层的 PDF；缺少 OCR 时保留图片并提示补充文字。

“补充／校正文字”保存为新版本，旧提取片段退出搜索，原件保持不变；引用位置改为校正文字行号。
搜索为有上限的关键词子串检索，最多返回 20 个片段，尚非语义向量检索。

## 安装

基础计划管理、Markdown/TXT/DOCX 提取使用 Python 标准库。完整 PDF 和图片支持安装：

```powershell
python -m pip install -r requirements-knowledge.txt
python -m studypet.web
```

PDF 使用 pypdf（BSD-3-Clause），图片校验使用 Pillow（本机安装版本标注 MIT-CMU）；Windows OCR 使用 PyWinRT 投影（MIT）调用系统 API。
安装依赖需要联网，导入/提取/检索过程不调用云端模型、OCR 或其它上传服务。

参考：[pypdf 文字提取](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)、[Windows OCR API](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine)。

## 存储和版本

- 主库为 `.local/studypet.sqlite3`，当前正式 schema 为 **v3**。资料分类存于 `documents.category`。
- 新增 `documents`、`document_chunks`、`sources` 三表，共 8 张业务表。
- 原件在 `.local/attachments/<document_id>/1/original.<ext>`，原始用户文件不修改。
- 更正后的文字版本保存在数据库，原件路径不随文字修订移动。
- 内容 SHA-256 去重，完全相同文件不会重复保存；已删除文件可重新导入。
- 来源默认 `local_only`；当前搜索页面是本地访问，尚未提供云端处理范围的切换。
- 文字或检索开关变化递增 revision，旧来源失效；并发保存检测版本冲突。
- 删除保留无正文的技术元数据（ID、哈希、时间等），不会声称清除旧备份或操作系统残留。

主库迁移统一由 `studypet/storage/migrate.py` 执行；正式增量 SQL 位于 `storage/migrations/0002_document_library.sql`。
旧 5 表与历史保持原样，旧库的原始创建/完成时间仍保持未知。架构目录里的 proposed_v2.sql 是早期完整助理草案，不能对当前真实库执行。

首次升级前已备份。后续备份需同时包含 SQLite 一致快照和所引用的 attachments 文件，导入/删除时不要手工只复制一个正在写入的主库文件。
`.local/` 已被 Git 忽略，资料和识别结果不进入开源仓库。

## 与个人记忆的关系

资料库保存的是可查证材料。材料中的指令不作为程序规则，材料中的个人描述也不直接成为已确认档案。
后续 Context Builder 按问题、版本、来源状态和处理范围选取片段，再由模型生成回答或记忆候选。
这一步尚待实现，当前不会自动把资料注入 Codex 对话或外部聊天产品。
